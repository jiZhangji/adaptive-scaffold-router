# 两个研究思路的第一阶段结果

## 实验设置

- 模型：Qwen2.5-Math-1.5B
- 数据：Scaf-GRPO 官方 `Qwen2.5-Math-1.5B.parquet`
- 采样：从 source accuracy 为0的候选集中固定种子选择12题
- 每个条件2次 rollout，共24条配对轨迹
- 最大生成长度1024 token；完整 `\boxed{}` 后提前停止
- 温度0.7，单张 RTX 3090

这些结果是机制探针，不是完整多步 RL 训练结果。12题样本较小，数值用于决定研究方向，不用于论文主结论。

## 思路一：能力匹配的脚手架课程

### 主要结果

| 条件 | Rollout准确率 | 平均提示token |
|---|---:|---:|
| 无提示 | 33.3% | 0 |
| Knowledge@25 | 50.0% | 50.5 |
| Knowledge@50 | 58.3% | 109.3 |
| Planning@25 | 50.0% | 61.0 |
| Planning@50 | 58.3% | 117.8 |
| Planning@100 | 66.7% | 245.3 |
| Solution@25 | 41.7% | 62.0 |
| Solution@50 | 58.3% | 145.0 |
| Solution@100 | 62.5% | 352.1 |

- 5/12 道无提示全错题被至少一种提示恢复，rescue rate 为41.7%。
- 公开 Scaf 式渐进搜索成功率为87.5%，平均约2869总token、2.92次调用。
- 在相同87.5%成功率下，hindsight最低成本选择平均约787总token，理论节省72.6%。
- 课程控制器将12题分为：4题 `guided_root`、4题 `unguided_root`、2题 `decompose_or_defer`、2题 `unguided_probe`。

### 判断

该方向有明确的第一阶段正向证据：不同题目的有效提示类型和强度不同，且固定提示枚举存在较大的成本冗余。

但尚未证明子问题课程、提示退火和 off-context 修正能在 RL 后提升最终无提示性能。当前结论只能支持继续做完整训练，不能宣称完整方法已经成立。

## 思路二：MetaAsk / 最小信息主动求助

### 主要结果

| 条件 | 准确率 | 外部信息token | 无帮助失败样本恢复率 |
|---|---:|---:|---:|
| 无帮助 | 45.8% | 0 | — |
| 随机1-bit | 41.7% | 1 | 38.5% |
| 自主提问二元验证 | 16.7% | 1 | 7.7% |
| 受控答案正确性1-bit + 重试 | 20.8% | 1 | 7.7% |
| 最小Knowledge | 41.7% | 48.6 | 30.8% |
| 最小Planning | 37.5% | 59.5 | 30.8% |
| 最小Solution Step | 58.3% | 60.0 | 38.5% |

自主提问诊断显示：

- 24/24 次 Oracle 都只能解析为 `UNKNOWN`；
- 11/24 次没有生成有效 `<state>` 和 `<verify>`，退化为默认问题；
- 典型的自主问题只是 `...?`；
- 相对配对无帮助轨迹，只恢复1条，却破坏8条原本正确的轨迹。

为区分“不会提问”和“1-bit反馈本身无效”，又增加了受控答案验证：环境直接告诉模型上一次最终答案 YES/NO，再让模型重试。该条件准确率仍只有20.8%，说明当前1.5B基础模型也缺少利用稀疏纠错反馈完成自我修正的能力。

### 判断

当前 MetaAsk 实现没有效果，不能进入昂贵的完整 RL 阶段。结果更支持 Assistance Mismatch 的观点：这批困难题中，部分样本确实需要具体知识或步骤，而不是单个二元判断。

该负结果不能证明 MetaAsk 概念永远不可行，因为当前 ASK policy 和 Oracle 都由非指令微调的1.5B基础模型承担。下一轮至少需要：

1. 使用 instruction-tuned 或更强模型生成结构化 proposition；
2. 使用可靠的符号验证器或独立强 Oracle，避免全部 `UNKNOWN`；
3. 先监督训练 ASK 格式和问题价值，再做在线 RL；
4. 在相同总生成token下比较，避免多轮重试带来的计算不公平；
5. 先识别 epistemic-error 子集，再测试二元验证，而不是对所有知识缺失题统一使用1-bit反馈。

## 当前研究决策

- 优先推进思路一的真实 RL：子问题门控、能力匹配脚手架、退火和重要性修正。
- MetaAsk 暂时作为高风险支线；先解决结构化提问与可靠验证，再重新评估，不直接投入完整 GRPO 训练。
